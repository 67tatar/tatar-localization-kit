# Татарская локализация приложений

## Overview

Главный фреймворк скилла: порядок работы над локализацией UI на татарский
язык. Работа ведётся в паре: агент предлагает варианты, проверяет их по
источникам и ведёт техническую часть; носитель языка задаёт направление и
выносит финальные решения. Каждый спорный термин и каждая ошибка закрепляются
в глоссарии или в SKILL.md — фреймворк растёт от практики, а не от
заочного конструирования правил.

## When to Use

- Перевод UI-строк (JSON, .properties, PO) на татарский.
- Проверка готовой татарской локализации.
- Наполнение и сверка глоссария.
- Не использовать для: проверки отдельного термина без контекста задачи
  (`tatar-text-research`), транслитерации (`tatar-transliteration`),
  оценки естественности целого текста (`tatar-text-eval`).

## Workflow

1. **Извлечь строки.** Найти файлы локализации, построить пары
   source→target с одинаковым набором ключей. Готово: полный список ключей.
2. **Терминология.** Сначала глоссарий `data/glossary.csv` (en,ru,tt,note,
   source,confidence). Чего нет — проверить по приоритету прецедента:
   tt-MediaWiki allmessages → узус tt-Википедии → словари
   (`tatar-text-research`). Готово: у каждого термина есть источник.
3. **Перевод** по языковым правилам ниже. Готово: ни одного термина без
   источника или пометки «не узуальное».
4. **QA.** `python scripts/qa_strings.py source.json target.json
   --glossary data/glossary.csv` — расхождения ключей, плейсхолдеры,
   непереведённое, дубликаты, глоссарий. Готово: ошибок 0, предупреждения
   разобраны.
5. **Отчёт.** Изменённые ключи; спорные термины с пометками; предложение
   дополнить глоссарий подтверждёнными вариантами. Готово: заказчик может
   принять решение по каждой спорной позиции.

## Языковые правила (проверенные, с источниками)

- **Числительное + существительное — в ед.ч.**: «биш китап» грамматично,
  «*биш китаплар» — калька (TatBLiMP; см. references/locale-standards.md).
- **Заимствования — норма**: файл, программа, сервер, клавиатура
  (узус tt-Википедии). Не русифицировать искусственно и не выдумывать
  «исконные» эквиваленты.
- **Plural-формы в i18n**: для tt действует только категория `other`
  (CLDR fallback на root) — plural-ветки фактически не нужны.
- **Форматы**: десятичная запятая, группировка пробелом (12 345,67);
  даты dd.MM.y / d MMMM, y 'ел' (см. references/locale-standards.md).
- **Алфавит и сортировка**: 39 букв, порядок закона № 997; Unicode-коллация
  порядок НЕ даёт — нужна своя collation-таблица (см. references/orthography.md).
- **Хамза/апостроф**: в кириллице передаётся э/ь/ъ без единой нормы; в
  латинице — апостроф (см. references/orthography.md).
- **Форма обращения**: по умолчанию вежливое «сез»; сверять с прецедентами
  tt-MediaWiki для данного типа продукта.

## QA-скрипт

`scripts/qa_strings.py` (только stdlib, тесты в `tests/`):

```bash
python scripts/qa_strings.py strings-ru.json strings-tt.json \
    --glossary data/glossary.csv --strict
```

Проверяет: парность ключей; плейсхолдеры ({name}, {0}, %s, %1$s, %(x)d);
непереведённые строки; дубликаты; пробелы по краям и управляющие символы;
аномальную длину; соблюдение глоссария. Коды возврата: 0 чисто, 1 ошибки,
2 только предупреждения (--strict превращает в ошибки). Форматы: JSON
(плоский/вложенный) и .properties.

## Common Pitfalls

1. **Кальки с русского** — конструкции типа «выполнение действия» переносятся
   в татарский плохо; каждое спорное слово — через `tatar-text-research`.
2. **Плейсхолдеры** — терять `{name}`/`%s` при переводе нельзя; QA ловит, но
   лучше не терять.
3. **Длина строк** — татарский текст часто длиннее русского; проверять лимиты
   кнопок и меню.
4. **Сортировка** — не полагаться на Unicode-порядок кодовых точек.
5. **Апостроф** — нормализовать ASCII `'` и U+02BC.
6. **Омоформы** — высокочастотные формы («башында») доказывают не то значение;
   проверять узус сниппетами, не totalhits.

## Verification Checklist

- [ ] qa_strings.py: ошибок 0, предупреждения разобраны.
- [ ] Все термины из глоссария применены; новое — с источником или пометкой.
- [ ] Плейсхолдеры и форматы нетронуты.
- [ ] Спорные позиции вынесены в отчёт заказчику, а не «замазаны».
